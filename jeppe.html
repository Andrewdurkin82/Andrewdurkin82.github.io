Case Study 01 · Personal Intelligence Layer

Jeppe

Jeppe is evolving into a user-owned intelligence layer that can work with whichever AI assistant or model you prefer. It started as a prompt-efficiency problem: stop making people explain themselves from scratch. The larger goal became portability — build an accurate, inspectable understanding of yourself that you control and can carry to the next model.

The mission

Your assistant can change. Your identity should not reset with it.

Jeppe began with a practical annoyance: good AI conversations become expensive and repetitive when every new chat needs the same background, preferences, history, and instructions pasted back into the prompt.

At first, the obvious answer was to build a personal assistant that remembered more. That idea changed. The assistant itself is not the part I want to own. People should be able to use the model or assistant they prefer while keeping control of the accumulated context that makes that assistant useful to them.

That turned Jeppe into an intelligence-layer problem. To make identity portable, the system has to decide what is actually known, where it came from, what changed, what conflicts, and which tiny slice of that context belongs in the current prompt. Memory retrieval is where much of the work sits today because portability is useless if the layer sends the wrong version of you to the model.

Design principles

The user owns the context. The model earns access to it.

Your context is portable

The long-term asset is the user’s accumulated identity and history, not loyalty to a particular answer model.

Models stay replaceable

Jeppe should work with a preferred assistant rather than forcing the user into a single model, provider, or interface.

Evidence before interpretation

Derived memories point back to source evidence, corrections, and conflicts instead of silently becoming “truth.”

Context has to earn its place

Prompt efficiency means sending the smallest useful context, not dumping a biography into every request.

What I built

The intelligence layer became a retrieval problem.

Evidence-backed memory

Source spans, correction lineage, supersession, retraction, validation state, and user review controls.

Context retrieval

Deterministic lexical retrieval plus optional local MiniLM semantic retrieval, conflict grouping, and explicit inclusion/exclusion reasoning.

Context Builder

A provider-neutral selection layer that assembles bounded personal context independently from the answer model.

Evaluation harnesses

Frozen synthetic scenarios, retrieval metrics, sufficiency tests, ablations, live generated-answer experiments, and blinded review.

Multi-user foundation

Authenticated accounts with separated conversations, context, evidence, permissions, and imported history.

Deployment

A working FastAPI/SQLite application running on a dedicated Windows workstation with private remote access.

Evaluation

I did not want “seems better” to be the metric.

Prompt efficiency was the original goal, but shorter prompts are worthless if they leave out something the model actually needs. Jeppe now evaluates retrieval, context sufficiency, minimization, model planning, and generated-answer quality separately so “less context” never becomes a goal at the expense of a worse answer.

The point was not to prove that less context is always better. It was to build a way to measure when extra context helps, when it is irrelevant, and when removing it changes the answer.

Evolution

The product changed once the assistant stopped being the point.

Original idea

Stop rebuilding the prompt

The first goal was efficiency: preserve useful personal context so every conversation did not begin with another manual explanation of who the user is.

Assistant

Build something that remembers

Jeppe initially looked like a personal assistant with its own conversations, memory, permissions, and behavior.

Intelligence layer

The assistant became replaceable

The concept shifted toward a provider-neutral layer that owns context while the user chooses the assistant or model that actually answers.

Current work

Memory retrieval became the hard part

Portable identity requires accurate selection. The system now spends much of its engineering effort on evidence, conflicts, ranking, bounded context, benchmarks, and failure analysis.

Destination

Take yourself to the next model

The long-term goal is a user-owned identity and context layer that can move with you instead of being stranded inside whichever AI product you used last.

What it taught me

The assistant should be replaceable. Your context should not be.

Jeppe started as a way to make prompts smaller. It became a question of ownership: can a person keep the useful understanding an AI has built about them, inspect it, correct it, and bring it to whatever model they choose next? Retrieval is the work in front of that goal right now.

Back to the portfolio

The model is a component. The user’s context is the durable layer.

Jeppe is still evolving, and the retrieval problem is very much unfinished. The direction is clearer now: give people a way to own the accumulated identity and context that makes AI personal, then let them choose which assistant gets to use it.
