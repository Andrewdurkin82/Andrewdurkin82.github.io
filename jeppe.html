Case Study 01 · Personal AI

Jeppe

A personal AI system built around a simple question: if an assistant remembers something about you, how can it know whether that information is trustworthy enough to use?

The problem

Personalization is easy. Trustworthy personalization is not.

LLMs can sound confident even when the personal context underneath an answer is stale, conflicting, weakly sourced, or simply irrelevant.

I wanted Jeppe to treat personal context as evidence rather than invisible intuition. A useful assistant should be able to preserve what a user actually said, distinguish that from later interpretation, keep conflicts unresolved when they really are unresolved, and expose enough provenance for the user to inspect or correct the system.

That changed the project from “build a chatbot with memory” into a larger systems problem involving retrieval, trust, privacy, lifecycle state, evaluation, and model behavior.

Design principles

The system is designed to fail conservatively.

Evidence before interpretation

User and assistant text are retained as evidence. Derived memories reference evidence rather than silently replacing it.

Conflicts stay conflicts

Competing claims are preserved together. The system does not invent a winner simply because one answer would be more convenient.

Current permission wins

External processing is controlled by deterministic application logic, not by hoping a model correctly interprets a privacy instruction.

Context has to earn its place

Retrieval is bounded and inspectable. More personal information is not automatically better information.

What I built

From memory storage to an evaluated context system.

Evidence-backed memory

Source spans, correction lineage, supersession, retraction, validation state, and user review controls.

Context retrieval

Deterministic lexical retrieval plus optional local MiniLM semantic retrieval, conflict grouping, and explicit inclusion/exclusion reasoning.

Context Builder

A provider-neutral selection layer that assembles bounded personal context independently from the answer model.

Evaluation harnesses

Frozen synthetic scenarios, retrieval metrics, sufficiency tests, ablations, live generated-answer experiments, and blinded review.

Multi-user foundation

Authenticated accounts with separated conversations, context, evidence, permissions, and imported history.

Deployment

A working FastAPI/SQLite application running on a dedicated Windows workstation with private remote access.

Evaluation

I did not want “seems better” to be the metric.

Jeppe has separate evaluation for retrieval, context sufficiency, minimization, model planning, and generated-answer quality. Experimental systems remain separate from production authority so a promising benchmark result cannot quietly rewrite the product.

16 / 19

Required-fact recall on the improved hybrid retrieval holdout, while irrelevant inclusions were reduced from 6 to 3.

27.79%

Personal-context reduction in the oracle minimal packets used in controlled generated-answer evaluation.

16 / 16

Full-vs-minimal answer pairs judged quality-preserving in blinded semantic review after the live experiment.

The point was not to prove that less context is always better. It was to build a way to measure when extra context helps, when it is irrelevant, and when removing it changes the answer.

Evolution

The project changed as the questions got harder.

Foundation

Conversation + evidence

Started with authenticated conversations, immutable evidence, explicit processing policy, and a provider-neutral behavior layer.

Memory

Provenance + lifecycle

Added source-backed memories, correction and retraction controls, conflict handling, and conservative admission.

Retrieval

Selection became its own system

Built lexical and hybrid retrieval, bounded packets, decision traces, benchmarks, and holdout validation.

Evaluation

From retrieval metrics to answer quality

Added sufficiency tests, ablations, automated minimization, live answer experiments, and blinded review.

Product

Usability and portability

Added multi-user setup, review tools, provider/model provenance, history import, private remote access, and a cleaner chat interface.

What it taught me

The hardest part of an AI system is often not getting the model to answer. It is deciding what information the model deserves to see before it answers.

Jeppe pushed me toward a systems view of AI: model capability matters, but so do provenance, permissions, retrieval quality, failure handling, evaluation design, and the interface where a human can correct the machine.
